# Курс по ROS 2

> [!WARNING]
> Если вы студент ИТМО, используйте методическое пособие Операционная система для роботов ROS2
>
> README.MD только для тех, кто не обучается в ИТМО! 


Материалы курса, шаблоны пакетов, практические задания и структурированные
заготовки для сдачи лабораторных работ по разработке программного обеспечения
для роботов с использованием ROS 2.

Курс рассчитан на **ROS 2 Jazzy**, **Ubuntu 24.04** и **Gazebo Harmonic**.
Он охватывает путь от основ взаимодействия в ROS до моделирования роботов,
управления с обратной связью, работы с датчиками и интеграции физического
оборудования.

## Темы курса

- Ubuntu, установка ROS 2, рабочие пространства, пакеты и `colcon`
- Узлы, топики, сообщения, параметры, пространства имён и launch-файлы
- Quality of Service, время ROS, журналирование и диагностика из командной строки
- Пользовательские сообщения, сервисы и действия
- TF2, URDF, Xacro, `robot_state_publisher` и RViz2
- Симуляция в Gazebo и `ros_gz_bridge`
- Кинематика дифференциального привода и `ros2_control`
- Симуляция камеры и лидара, обработка данных датчиков
- Взаимодействие с Arduino, обратная связь от энкодеров и аппаратные драйверы

## Лабораторные работы

1. **Пакет и контроллер ROS 2** — запустить две системы turtlesim в отдельных
   пространствах имён, провести первую черепаху через заданные точки и
   реализовать следование второй черепахи за её положением.
2. **Пользовательские сервисы и действия** — создать пакет интерфейсов с
   выбранным студентом именем и реализовать клиенты и серверы сервисов/действий
   в `lab2_controller`.
3. **Модель робота** — описать мобильного робота и манипулятор в соответствии
   с вариантом с помощью Xacro, а затем визуализировать модель и дерево TF в
   RViz2.
4. **Симуляция и управление** — смоделировать робота с дифференциальным
   приводом, управлять его сочленениями через `ros2_control` и преобразовывать
   `/cmd_vel` в скорости колёс.
5. **Датчики и автономное поведение** — добавить камеру и лидар, создать
   наполненный объектами мир симуляции и реализовать поведение на основе
   обратной связи от датчиков.
6. **Интеграция оборудования** — реализовать Python-драйвер ROS и интегрировать
   аппаратный плагин Arduino, передачу команд и обратную связь от энкодеров.

Размеры, целевые точки, параметры датчиков и критерии оценивания для каждого
варианта определены в учебном пособии. Вариант студента выбирается по последней
цифре его номера ИСУ ИТМО.

Каждый каталог `labN` является обычным контейнером для сдачи работы, а не
пакетом ROS. Метаданные пакетов должны находиться внутри показанных выше
каталогов пакетов. Требуемые имена и пути являются частью контракта системы
автоматической проверки.

- [Установка ROS 2 Jazzy — английский](install_ros2_jazzy.html)
- [Установка ROS 2 Jazzy — русский](install_ros2_jazzy_ru.html)

Основная целевая платформа — Ubuntu 24.04 с ROS 2 Jazzy и Gazebo Harmonic.
Среда Docker предоставляет те же зависимости курса и подключает этот
репозиторий по пути `/workspace`.

## Сборка пакетов

Из корня репозитория:

```bash
source /opt/ros/jazzy/setup.bash
rosdep update
rosdep install --from-paths . --ignore-src --rosdistro jazzy -y
colcon build --symlink-install
source install/setup.bash
```

При работе над отдельной лабораторной можно собрать один пакет и его
зависимости:

```bash
colcon build --symlink-install --packages-up-to my_best_model
```

Вывести список пакетов, обнаруженных в репозитории:

```bash
colcon list --base-paths lab1 lab2 lab3 lab4 lab5 lab6
```

## Запуск пакетов лабораторных работ

Примеры с установленными именами launch-файлов:

```bash
ros2 launch mybestcontroller lab1.launch.py
ros2 launch my_best_model rviz.launch.py
ros2 launch my_best_robot_simulation_control simulation_control.launch.py
ros2 launch my_best_robot_simulation_setup simulation_final.launch.py
```

Команды запуска для лабораторных работ 2 и 6 зависят от исполняемых файлов и
launch-файлов, реализованных студентом. Смотрите README соответствующей
лабораторной работы.

## Правила сдачи

- Размещайте исходные файлы только в соответствующем каталоге `labN`.
- Сохраняйте все требуемые имена каталогов, пакетов, интерфейсов и launch-файлов.
- Храните метаданные пакета ROS внутри каталога этого пакета.
- Не добавляйте в репозиторий `build/`, `install/`, `log/`, кеши и созданные
  Python файлы.
- Указывайте зависимости в `package.xml` и метаданных системы сборки пакета.
- Убедитесь, что пакеты собираются в чистом рабочем пространстве.
- Перед сдачей проверьте требуемые команды запуска и интерфейсы ROS.
- Сдавайте оригинальную работу: стартовые материалы не являются готовым
  решением лабораторных работ.
